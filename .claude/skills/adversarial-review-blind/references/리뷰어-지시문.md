# 리뷰어 지시문 템플릿

리뷰어 A와 B에게 **글자 그대로 동일하게** 넘긴다. `<>` 자리만 채우고 나머지는 바꾸지 않는다. A와 B에게 서로 다른 힌트·강조·예시를 주면 교차 재현이 통계적 의미를 잃는다.

메인의 선행 finding, 이전 리뷰 결과, 다른 리뷰어의 존재는 **주지 않는다.**

```
너는 이 기획 문서들을 처음 보는 독립 리뷰어다. 이 문서에 대한 소유권도 없고,
누가 썼는지도 모르며, 이전에 어떤 리뷰가 있었는지도 모른다.

너의 일은 이 기획이 하류 작업으로 넘어가기 전에 결함을 찾아내는 것이다.
문장을 다듬는 제안은 필요 없다. 실제로 이 프로젝트를 헛돌게 만들 것들을 찾아라.

## 대상 문서
<파일 경로 목록. 각 줄에 문서 종류 표기.>

## 기준점
줄 번호는 HEAD `<short-sha>` 시점 기준이다. <미커밋 변경 목록 또는 "작업 트리 clean">

## 읽어야 할 공격축
1. 먼저 `.claude/skills/adversarial-review-blind/SKILL.md`의 §2 공통축을 읽고 전 문서에 적용한다.
2. 그다음 위 목록의 각 문서 종류에 해당하는
   `.claude/skills/adversarial-review-blind/references/공격축-*.md`를 읽고 적용한다.
공격축은 체크리스트다. 모든 축을 고려하되, 축마다 finding이 나올 필요는 없다.
축에 없는 결함을 찾았으면 그것도 보고한다.

## 먼저 할 일
finding을 쓰기 전에, 이 기획이 무엇을 하려는 것인지 **네 말로 한 문단** 요약하라.
문서의 문장을 복사하지 말고 네가 이해한 대로 쓴다.

## 규칙
- 모든 주장에 `파일:줄` 근거를 단다. 근거 없는 주장은 보고하지 않는다.
- 문서가 이미 말한 것을 되풀이하지 않는다. "이 문서는 X를 정의한다"는 finding이 아니다.
- 저자가 아니라 문서를 공격한다. "명세가 X를 다루지 않는다"이지 "X를 빠뜨렸다"가 아니다.
- 맥락이 없어 판단할 수 없으면 추측으로 메우지 말고 "판단 불가"라고 쓴다.
  그래도 쓸 값어치가 있는 추측이면 심각도 뒤에 (추측)을 붙인다.
- 문서를 고치지 마라. 너는 리뷰어지 편집자가 아니다.
- 문서가 명백한 초안·스텁이면 먼저 그렇게 말하고 가장 중요한 공백만 짚는다.
  세 절을 "미기재"로 채우지 않는다.
- 문서가 견고하면 견고하다고 말한다. 철저해 보이려고 우려를 발명하지 마라.
  다만 복잡한 문서에서 0건이 나오면 네가 실제로 읽었는지 스스로 의심하라.
- `mcp__rejectbench-evidence__guard_evidence`와 `get_report`를 호출하지 마라.
  이 리뷰는 문서만 읽는다. 판정 API 과금 호출도 하지 않는다.

## 심각도
- 치명: 이 상태로 하류에 진입하면 산출물이 무의미해진다
- 중대: 하류 작업 중 반드시 재작업을 부른다
- 보통: 나중에 비용을 치른다
- 경미: 오독·혼란을 부른다
전부 치명이면 아무것도 치명이 아니다. 등급을 부풀리지 마라.

## 출력 형식
먼저 목적 요약 한 문단. 그다음 finding을 번호 순으로:

  ### F1. <한 줄 제목>
  - **심각도**: 치명 | 중대 | 보통 | 경미  (+ 필요시 (추측))
  - **축**: <어느 공격축에서 나왔는가>
  - **근거**: `파일:줄` — <그 줄에 실제로 뭐가 쓰여 있는지 인용>
  - **문제**: <무엇이 잘못됐고 왜 중요한가>
  - **권고**: <무엇을 정하거나 추가하면 해소되는가. 구체적으로>

마지막에 **"견고한 부분"** 2~4문장. 정직하게 — 얇으면 얇다고 쓴다.

너의 최종 텍스트가 반환값이다. 인사말이나 맺음말을 쓰지 마라.
```

## 리뷰어 수

기본은 2명(A·B)이다. 대상이 한 사이클 전체(문서 6개 이상)면 3명까지 늘린다. 늘릴 때도 지시문은 동일하고 대상 문서 목록도 동일하다 — **문서를 나눠 주지 않는다.** 나누면 교차 재현이 불가능해지고, 문서 간 전파 손실(공통축 §2.4)을 아무도 못 본다.

# Reject Bench

여러 AI 코딩 세션에서 지속형 가드가 왜 발동했는지 남기고, 그 증거로 가드를 유지·수정·제거하기 위한 개인 도구 실험입니다.

## 현재 상태

**v7 설계 승인·기존 구현 정리 완료 단계**입니다. 문제정의를 다시 열어 기존 “거부 장면 + 단일 오탐률 + 공개 원장” 계획을 폐기하고, 가드 수명주기 결정 중심으로 처음부터 다시 설계했습니다.

아직 v7 기능 구현은 없습니다. 이전 `rejectbench/`, `tests/`, `docs/형식-표준.md`는 전용 D1 정리 커밋에서 폐기했고 git 이력에만 남겼습니다. 다음 구현 단계는 v7 도메인 계약 T1입니다.

## 해결하려는 문제

> 여러 AI 코딩 세션에서 지속형 가드를 운영하는 1인 개발자는, 가드 발동 사건과 당시 맥락이 구조화되어 남지 않아 그 가드가 명시 정책대로 막았는지와 실제로 도움이 됐는지 검증할 수 없고, 결국 기억과 흩어진 오류 로그에 의존해 가드를 유지·수정·제거한다.

현재 문제정의 정본: [`docs/문제정의/06-v7-문제정의.md`](docs/문제정의/06-v7-문제정의.md)

## v7이 분리하는 두 판단

- **정책 일치성**: 사건 당시 버전으로 고정된 가드 맥락을 받은 독립 LLM이 판단
- **실제 유용성**: 사용자가 작업에 도움이 됐는지 판단하고 가드의 `keep`, `modify`, `remove`를 결정

정책대로 막았지만 불필요할 수 있고, 정책과 어긋났지만 우연히 도움 될 수도 있으므로 둘을 하나의 오탐률로 합치지 않습니다.

## 최소 사용자 가치 증거

같은 지속형 가드가 여러 세션에서 자연 발동하고, 각 사건의 LLM 정책 판정과 사용자 유용성 검토를 거쳐 근거가 연결된 가드 결정 1건이 나와야 합니다.

강제로 만든 시험 사건은 기술 파이프라인 검증에만 사용합니다. 시험만 통과했거나 자연 운영 사건 분모가 0이면 사용자 가치는 **미검증**입니다.

## 기존 수집기 v0

`hooks/collect.py`는 기존 실측 원천을 계속 쌓는 이전 수집기입니다. 실제 가드 거부를 구조화해 잡지 못했다는 사실이 v7 재설계의 출발점이었습니다. 새 기록기가 실제 가드에 연결될 때까지 관측 공백을 피하려고 유지하며, 이후 별도 결정으로 퇴역시킵니다.

## 세션 연속성

`HANDOFF.md`가 Claude Code와 Codex 세션 사이의 유일한 현재 상태 문서입니다. `hooks/continuity.py`와 `hooks/codex_handoff_gate.py`가 compact 전에 최신 HANDOFF와 Git 상태를 OS 임시 디렉터리에 스냅샷하고 다음 컨텍스트에 주입합니다. transcript·프롬프트·도구 출력은 저장하지 않습니다.

## 주장 범위

v1의 최대 주장은 다음뿐입니다.

> 내 저장소에서 사라지던 가드 발동을 증거 기반 가드 결정으로 바꾸는 개인 도구 실험.

다른 사용자·팀·생산성·AI 코드 품질·시장 수요는 실제 외부 사용 전까지 주장하지 않습니다.

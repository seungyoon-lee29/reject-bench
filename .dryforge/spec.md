# Reject Bench 증거 조회 MCP 서버 — 행동 계약

작성 2026-08-29. v1 본체(T1~T6)의 행동 계약은 [`001/spec.md`](001/spec.md)로 아카이브돼 있고 여전히 유효하다 — 이 문서는 그 계약이 "관찰 대기 구간의 선택 증분 T7"로 미뤄 뒀던 증거 조회 표면 하나만 범위 안으로 들여와 정의한다. 이 증분은 v1 본체의 행동·기록·지표를 바꾸지 않는다. [`기획-입력.md`](../기획-입력.md)의 불변 결정은 이 문서보다 상위다.

## 1. 목적

관측창 대기 구간에, AI 코딩 세션이 reject-bench의 보고서와 가드별 증거를 **읽기 전용으로** 조회할 수 있는 최소 MCP 서버를 만든다. 기록·판정·검토·결정은 계속 기존 CLI만 쓴다. 이 표면은 v1 완료 조건·가치 주장과 무관한 조회 편의이며, 관측 지표에 어떤 영향도 주지 않는다.

## 2. 범위

### 포함

- MCP 서버 모듈 1개(stdio)와 읽기 도구 3종: 가드 목록, 가드별 증거, 전체 보고서 (2026-08-29 사용자 결정)
- 모든 도구 응답에 대한 출력 경계 정화(홈 경로·세션 식별자 비노출)와 그 자동 검증
- reject-bench 저장소 로컬 `.mcp.json` 등록 (2026-08-29 사용자 결정 — 전역 등록은 이번 범위 밖)
- 공식 MCP Python SDK 의존성 추가 (2026-08-29 사용자 결정)

### 제외

- 쓰기·수정·삭제 도구 일절 (아카이브 계약 T7 원문: "쓰기 도구 없음")
- 전역 등록, 원격 전송(HTTP/SSE), 네트워크 노출 — stdio 로컬 전용
- 검토 대기 큐 도구 (사용자가 3종 최소 구성을 선택하며 제외)
- 기존 CLI·기록 경로·판정 경로·보고서 내용의 변경
- 관찰 프로토콜·관측 범위의 변경 (조회 표면은 관측 런타임이 아니다)

## 3. 서버 계약

- 모듈은 `rejectbench` 패키지 하위 신설 모듈이며, `python -m` 실행 진입점을 가진다. **기존 모듈은 수정하지 않는다** — 조회 표면은 기존 공개 함수(등록부 조회, 가드 뷰 구성, 보고서 생성)를 임포트해 조합하고, 내보내기 안전 투영은 신설 모듈 안에서 한다.
- MCP SDK 임포트는 신설 모듈에 국한한다. v1 본체 코드는 SDK 없이도 지금과 동일하게 동작해야 한다.
- store 인자: 기본값은 운영 중앙 경로(`data/v7`, 패키지 위치 기준)이고, `--store DIR`로 대체할 수 있다(테스트·검사용). 테스트는 임시 디렉터리 store만 쓴다 — 운영 store 접촉은 기존 conftest 게이트가 하드 실패시키며 이 게이트를 유지한다.
- 신선도: 도구 호출마다 store를 다시 적재한다. 캐시·상주 상태를 두지 않는다. 기록기가 동시에 append 중이어도 안전하다 — 부분 꼬리 줄은 기존 적재 의미대로 건너뛰고 손상 줄 수로 가시화한다.

### 읽기 전용 계약 (정밀 선언)

서버가 디스크에서 읽는 범위는 정확히 다음 둘뿐이다.

1. store 루트의 레코드 파일들: `records.jsonl`, 사이드카 `calibration.jsonl`, 기준선 `baseline.json`
2. 등록된 `enforcement_ref`가 가리키는 가드 스크립트의 **바이트**(해시 대조용 — 기존 구현물 대조 로직 재사용)

서버는 어떤 파일·디렉터리도 생성·변경·append하지 않는다. store가 없어도 디렉터리를 만들지 않는다. 보고서를 파일로 쓰는 경로(`--out` 상당)를 노출하지 않는다. 임의 코드 실행 금지는 v1 본체 계약 그대로다 — 가드 스크립트는 바이트 읽기만 하고 절대 실행하지 않는다.

## 4. 도구 계약

세 도구 모두 응답은 MCP text 콘텐츠다. 가드 목록·가드별 증거는 JSON 직렬화 텍스트, 전체 보고서는 Markdown 텍스트다. 도구 이름·JSON 키 이름은 아래를 기본값으로 하되 조정 가능(tunable)이다 — 단, 아래 "필수 내용"은 이름을 바꿔도 반드시 담는다.

### 4.1 `list_guards` — 가드 목록

입력 없음. 등록된 가드 전부를 반환한다: 가드별 `guard_id`, `project`, `latest_version`, `versions`. 등록 가드가 없으면 빈 목록(오류 아님).

### 4.2 `guard_evidence` — 가드별 증거

입력: `guard_id`(필수), `version`(선택 — 생략 시 맥락은 최신 버전 기준). 반환 JSON의 필수 내용:

- **가드 맥락**: 해당 GuardSpec의 의미 5필드(`purpose`, `policy`, `exceptions`, `allow_examples`, `block_examples`)와 `version`, `content_hash`, 버전 목록, 구현물 대조 상태(`in_sync | drift | unverifiable`)와 그 사유
- **세션 집계**: 운영 세션 수, 판정 가능 세션 수, 판정 가능 가드 여부(기준 문구 포함)
- **사건 목록** (등록 사건 전부, append 순서): 사건별 `event_id`, `occurred_at`, 세션 별칭, 유효 출처(amendment 반영 파생값), `capture_status`, 행동 요약(`tool_name`, `command_verb`, `target_path`, `heredoc`), 차단 사유(`reason`), 정책 판정(값·사유·`model_id`·`judged_at`·교정 상태, 미처리면 그 표시), 유용성 검토(값·메모·`reviewed_at`, 미처리면 그 표시), 판정 가능 여부, `post-remove`·`drift`·`partial` 표시. 교정 상태의 값 집합은 `passed | failed | none`이다 — 판정의 (spec·루브릭·모델·설정) 조합과 일치하는 최신 교정 레코드의 통과 여부이고, 일치 레코드가 없으면(미교정 판정) `none`이다. 파생은 기존 단일 정의(같은 조합의 최신 교정 레코드 조회)를 재사용한다.
- **결정 이력** (append 순서): 결정별 `decision_id`, `decision`, `decided_at`, `evidence_event_ids`, `rationale`, `resulting_guard_version`, 가치 검증 산입 여부(`countable` — 저장값이 아닌 파생 계산), 발동 사건 없는 가드 표시, 산입 제외 사유
- **기록 건전성**: 손상 줄 수

미등록 `guard_id` 또는 존재하지 않는 `version` → MCP 도구 오류(isError)로 한 줄 사유만. 스택 트레이스·파일 시스템 경로를 오류 텍스트에 넣지 않는다.

### 4.3 `get_report` — 전체 보고서

입력 없음. 기존 보고서 생성 함수가 내는 Markdown 전문을 그대로 반환한다(내용 수정 없음 — 보고서 계약의 정본은 v1 본체다). store가 없거나 비어 있으면 보고서가 원래 내는 미검증/0건 상태 그대로 반환한다(오류 아님).

## 5. 출력 경계 정화 — 비노출 계약

아카이브 계약 §4("홈 경로와 세션 식별자는 공개 산출물로 내보내지 않는다")를 이 표면의 완료 조건으로 승격한다. MCP 응답은 내보내기 산출물로 취급한다.

- **적용 범위는 전 문자열이다**: 세 도구 응답(오류 응답 포함)에 들어가는 **모든** 문자열 값이 출력 직전에 정화 경계를 정확히 한 번 통과한다. 행동 요약의 `target_path`만이 아니라 차단 사유(`reason`), 검토 메모, 결정 사유(`rationale`), GuardSpec 의미 5필드, 구현물 대조 사유(`enforcement_ref`의 스크립트 경로 — 등록된 전역 가드는 홈 절대 경로로 저장돼 있다), 오류 메시지까지 포함한다.
- **홈 경로**: 실행 사용자의 홈 디렉터리 절대 경로 접두를 `~`로 치환한다. 경로 꼬리는 보존한다 — `target_path`는 판정 최소 필드라서 생략이 아니라 치환이어야 한다.
- **세션 식별자**: 레코드의 세션 식별자 원문은 어떤 응답에도 넣지 않는다. 가드별 증거 응답 **하나 안에서만** 유효한 연번 별칭(`S1`, `S2`, … — 첫 등장 순, 같은 세션은 같은 별칭, 다른 세션은 다른 별칭)으로 치환한다(2026-08-29 사용자 결정 — 판정 가능 근거인 사건-세션 대응을 보존하기 위해 집계-만 대신 별칭 선택). 응답 간 별칭 안정성은 보장하지 않으며, 별칭↔원문 매핑을 어디에도 저장하지 않는다(저장하면 쓰기 금지와 식별자 비지속 원칙을 동시에 깬다).
- **검증은 양성 대조로 한다**: 홈 경로와 세션 식별자를 실제로 심은 픽스처 store를 만들고, 세 도구 응답 전체(오류 경로 포함)를 스캔해 (a) 심은 홈 경로 원문과 실행 사용자 홈 절대 경로 문자열이 0회, (b) 심은 세션 식별자 원문이 0회, (c) 치환 결과(`~` 접두 경로, 별칭)가 실제로 존재함을 확인한다. 깨끗한 픽스처의 출력 스캔만으로는 통과로 치지 않는다.
- 비밀 제거는 적재 시점 규칙(v1 본체)이 이미 담당한다 — 이 경계는 그 위에 홈 경로·세션 식별자만 추가로 막는 것이며, 적재 시점 제거를 대체하지 않는다.

## 6. 등록 계약

- 저장소 루트 `.mcp.json`에 서버 항목 하나를 추가한다. 명령은 배선 관례를 따른다: `/Users/ian/.local/bin/uv run --project /Users/ian/workspace/reject-bench python -m <모듈>` (절대 경로 — 맨 `python3 -m`은 패키지를 못 찾는다).
- 전역 등록은 하지 않는다 (2026-08-29 사용자 결정). 근거: 첫 자연 사건의 기준선 측정은 도구 보고서 열람 전에 transcript+git 복원을 요구하는데, 전역 등록이면 다른 저장소 세션의 AI가 자동 조회해 이 규율과 부딪힐 수 있다. 전역 확장은 기준선 측정 뒤 별도 결정.
- Codex 배선은 만들지 않는다 — Codex 세션은 v1 관측 범위 밖이고 이 등록은 Claude Code 전용이다.

## 7. 의존성 결정

공식 MCP Python SDK를 프로젝트 의존성으로 추가한다 (2026-08-29 사용자 결정 — 표준 라이브러리 직접 구현 권고를 듣고도 SDK를 선택: 프로토콜 개정 추종 부담을 지지 않는 쪽을 택했고, 런타임 의존성 0 상태의 종료를 수용했다). 아카이브 계약 §4의 "표준 라이브러리 우선"에 대한 명시적 예외이며 범위는 이 조회 표면뿐이다 — v1 본체(기록·판정·검토·결정·보고서)는 계속 SDK 없이 동작한다. SDK 버전 핀은 조정 가능(tunable)이다.

## 8. 검증 계약

자동 검증(전부 임시 store, 네트워크 금지):

- 비노출 양성 대조 (§5 그대로 — 심은 픽스처, 세 도구 + 오류 경로 전수 스캔)
- 별칭 규칙: 같은 응답 내 같은 세션=같은 별칭, 다른 세션=다른 별칭, 원문 0회
- 읽기 전용: 도구 3종 호출 전후 store 디렉터리의 파일 목록·내용이 불변이고, store 부재 시 호출 후에도 디렉터리가 생기지 않는다
- 도구 계약: `guard_evidence` 필수 내용(§4.2) 존재, 미등록 가드·없는 버전의 오류 경로, 빈 store의 정상 응답, `get_report`가 기존 보고서 생성 함수 출력과 동일함 — 보고서에는 생성 시각 등 호출 시점 의존 행이 있으므로 동일성 비교는 같은 시각을 주입하거나 시각 의존 행을 정규화한 뒤 한다(방법은 조정 가능)
- MCP 왕복 스모크: 클라이언트로 initialize → tools/list(3종 확인) → 도구 3종 각각 호출 왕복 — SDK가 제공하는 시험 클라이언트(in-process 또는 stdio 하위 프로세스)로 수행
- 기존 전체 게이트 유지: `uv run pytest` 하나로 신규 테스트까지 전부 돈다 (hooks 연속성 회귀 포함)

수동 확인 1회(완료 게이트): `.mcp.json` 등록 경로로 실제 서버를 기동해 `list_guards` 호출 1건이 응답하는지 확인하고 종료한다. 도구를 `list_guards`로 못 박는 이유: 운영 store에 미검토 운영 사건이 있는 동안 기동 확인이 증거 전문·보고서를 세션에 실어 나르지 않게 — 노출 최소화이며 기준선 측정 규율과의 긴장을 피한다.

## 9. 주장 제한

이 표면은 조회 편의다. v1의 가치 가설(의사결정 시간·근거 복원·확신 개선)에 대한 어떤 증거도 만들지 않으며, 보고서·지표·관측 상태를 바꾸지 않는다. v1 최대 주장 문구는 그대로다.

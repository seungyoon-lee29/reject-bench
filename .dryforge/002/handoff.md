## 실행 모양

스캐폴드(`uv add mcp`) → T7-1(서버·정화·검증) → T7-2(로컬 등록·기동 확인). 순차 2태스크, 병렬 없음. 전체 게이트는 `uv run pytest` 하나(hooks 연속성 회귀 포함), 완료 게이트에 실기동 왕복 1건.

## 하드 게이트 (코드에서 유도할 수 없는 비협상 제약)

1. **쓰기 도구 0 · store 불변.** 서버는 어떤 파일·디렉터리도 생성·변경·append하지 않는다. 읽기 범위는 spec §3의 정밀 선언(레코드 파일들 + 가드 스크립트 바이트) 밖으로 넓히지 않는다. 가드 스크립트는 절대 실행하지 않는다.
2. **비노출 양성 대조 없이는 미완이다.** 홈 경로·세션 식별자를 값 전체·완전한 토큰으로 실제 심은 픽스처로 세 도구 + 오류 경로 전체를 스캔해야 한다(spec §5). 깨끗한 출력 스캔만으로 통과 선언 금지.
3. **테스트는 임시 store만.** 운영 `data/`에 닿으면 기존 conftest autouse 게이트가 하드 실패시킨다 — 이 게이트를 끄거나 완화하지 않는다. 네트워크 금지.
4. **SDK 임포트는 신설 모듈 국한, 기존 구현 모듈 무변경.** 구현 diff는 `pyproject.toml`·`uv.lock`(스캐폴드)과 신설 파일에 국한한다. 정본 정합성을 위한 주기 문서·규칙·루트 `HANDOFF.md` 갱신과 완료 뒤 `.dryforge/002/` 아카이브는 이 제한의 예외다. v1 본체는 SDK 없이 지금과 동일하게 동작해야 한다.
5. **새 행동은 red→green으로.** 실패 테스트 확인 후 구현 (구현층 테스트 규칙).

## 함정 (실행 중 걸리기 쉬운 것)

- **전역 가드 자기차단**: 위험 패턴 텍스트(예: 강제 push 문자열)가 픽스처·문서에 들어갈 때 heredoc/echo로 쓰면 전역 가드가 명령 전문 매칭으로 차단한다 — 파일 도구(Write/Edit)로 쓸 것. 이 발동 자체가 운영 사건으로 기록되니 주의.
- **이 저장소는 `.dryforge/` 계약 문서 3종을 git 추적한다**(`.gitignore` v2 정정 — `worktrees/`·`status.json`만 제외). go의 기본 `.dryforge/` gitignore 규칙을 적용해 추적을 풀지 말 것.
- **운영 store에 실레코드가 있다**(`data/v7/records.jsonl` 5건). T7-2의 기동 확인은 이 store를 읽기만 한다 — T7-1의 읽기 전용 검증이 선행 조건이다.
- `enforcement_ref.script_path`는 홈 절대 경로로 저장돼 있다(전역 가드) — 정화 경계가 이 값도 치환해야 한다(spec §5, 독립 감사 지적 사항).
- 배선·등록 명령은 `/Users/ian/.local/bin/uv run --project …` 절대 경로 관례 필수.

## 문서에 담기지 않은 저작 시점 의도

- **SDK 선택은 사용자가 권고를 기각한 결정이다**: 표준 라이브러리 직접 구현(의존성 0 유지)을 추천으로 제시했으나 사용자가 프로토콜 추종 부담 회피를 택했다. 실행자가 "의존성을 줄이는 개선"으로 stdlib 재구현으로 되돌리지 말 것.
- **검토 대기 큐 도구는 사용자가 제외를 선택**했다(3종 최소 구성). 추후 확장 여지는 있으나 이번에 몰래 넣지 말 것.
- **전역 등록 보류의 실질 이유**는 관찰 프로토콜의 기준선 측정 규율(도구 보고서 열람 전 transcript+git 복원)과의 충돌 위험이다. 기준선 측정 1회가 끝나면 전역 확장을 별도 결정할 수 있다.
- `guard_evidence`의 `version` 선택 입력은 기존 CLI `show --version` 조회 관례를 따른 파생 편의다 — 사용자 결정 사항이 아니므로 구현이 부담되면 최신 버전 고정으로 축소해도 계약 위반이 아니다(§4 필수 내용만 지키면 된다).

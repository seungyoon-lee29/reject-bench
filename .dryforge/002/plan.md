# 증거 조회 MCP 서버 — 실행 계획

작성 2026-08-29. 행동 계약은 [`spec.md`](spec.md)가 정본이다. v1 본체(T1~T6)와 관찰 로드맵(O1·O2·X1)의 계획은 [`001/plan.md`](../001/plan.md)에 아카이브돼 있고, 이 계획은 그 문서의 T7 항목을 이어받아 태스크 번호를 T7-*로 쓴다.

## 상태 표시

- `[ ]` 미착수 · `[~]` 진행 중 · `[x]` 완료 및 검증됨

## 스캐폴드 (태스크가 아님 — 오케스트레이터 인라인)

- 공식 MCP Python SDK 의존성 추가: `uv add mcp` (spec §7). `pyproject.toml`·`uv.lock`이 갱신된다. 이것 말고는 기존 파일을 건드리는 스캐폴드가 없다.
- `[tool.uv] package = false`와 pytest `pythonpath` 설정은 그대로 둔다 — 신설 모듈은 기존 `rejectbench/` 패키지 하위라서 추가 설정이 필요 없다.

## T7-1 — 조회 서버 모듈·출력 경계 정화·도구 3종

의존: 없음 (스캐폴드 뒤).

행동 계약: spec §3(서버·읽기 전용), §4(도구 3종 — `guard_evidence` 필수 내용 전부), §5(출력 경계 정화 — 모든 레코드 유래 문자열 값, 고정 키 보존, 홈 경로 `~` 치환, 완전 토큰 세션 별칭, 양성 대조), §8 자동 검증 전부.

- [x] 신설 모듈(`rejectbench/` 하위)에 stdio MCP 서버와 도구 3종 구현 — 기존 모듈 무변경, SDK 임포트는 신설 모듈 국한
- [x] 내보내기 안전 투영: 기존 가드 뷰·보고서·등록부 공개 함수를 조합하고, 출력 직전 정화 경계 1회(홈 경로 접두 `~` 치환 + 값 전체·완전한 토큰의 세션 별칭 치환)를 모든 레코드 유래 문자열 값에 적용(고정 JSON 키 보존)
- [x] `--store DIR` 인자(기본 운영 중앙 경로), 호출마다 재적재, 캐시 없음
- [x] 오류 계약: 미등록 가드·없는 버전 → isError 한 줄 사유(경로·스택 없음), 빈 store → 정상 응답
- [x] 테스트(red→green, 전부 임시 store): 비노출 양성 대조(심은 홈 경로·세션 id 픽스처, 세 도구 + 오류 경로 전수 스캔), 별칭 규칙, 읽기 전용(호출 전후 store 불변·디렉터리 미생성), `guard_evidence` 필수 내용, `get_report` 동일성, MCP 왕복 스모크(initialize → tools/list → 도구 3종 호출, SDK 시험 클라이언트, 네트워크 없음)

작업 대상: `rejectbench/` 하위 신설 모듈 파일, `tests/` 신설 테스트 파일. 검증 게이트: `uv run pytest` exit 0 (기존 357건 + 신규 전부).

생각-근거: 정화를 "출력 직전 경계 1회"로 강제하는 이유 — 필드별 선별 정화는 누락 경로(오류 메시지, 구현물 대조 사유의 홈 절대 경로 등)를 만들기 쉽고, 독립 감사가 이 누락을 실제로 지적했다. 경계 한 곳이면 새 필드가 생겨도 기본이 안전 쪽이다.

## T7-2 — 저장소 로컬 등록과 기동 확인

의존: T7-1 (등록이 가리키는 서버가 먼저 존재해야 한다 — 산출물 소비 간선).

행동 계약: spec §6(등록), §8 수동 확인.

- [x] 저장소 루트 `.mcp.json`에 서버 항목 1개 추가 — 명령은 `/Users/ian/.local/bin/uv run --project /Users/ian/workspace/reject-bench python -m <모듈>` 절대 경로 관례
- [x] 등록 경로 그대로 실제 서버 기동 → `list_guards` 호출 1건 왕복 확인 → 종료 (출력 캡처). 도구는 `list_guards`로 고정한다(spec §8 — 미검토 운영 사건이 있는 store에서 증거 전문·보고서를 세션에 싣지 않기 위해). 이 확인은 운영 store를 **읽기만** 한다 — T7-1의 읽기 전용 검증이 선행돼 있다
- [x] 전역 등록·Codex 배선을 만들지 않았는지 확인 (spec §6)

작업 대상: `.mcp.json` 신설(추적 대상 — 이 저장소 `.gitignore`는 이 파일을 무시하지 않는다). 검증 게이트: JSON 파싱 성공 + 기동 왕복 1건의 캡처된 증거.

## 공유 쓰기 안내

두 태스크의 작업 대상은 전부 신설 파일이고 서로 겹치지 않는다. 어느 태스크도 `pyproject.toml`·`uv.lock`(스캐폴드 소관)과 기존 `rejectbench/`·`tests/` 파일을 수정하지 않는다.

## 단계 서사

스캐폴드가 SDK를 추가하면, T7-1이 서버·정화·검증 전부를 세우고, T7-2가 그 서버를 이 저장소에 등록하고 실기동을 확인한다. 순차 2단계이며 병렬 여지는 없다.

## 실행 그래프

```yaml
tasks:
  - id: T7-1
    depends: []
    risk: RISKY
  - id: T7-2
    depends: [T7-1]
    risk: NONE
regen_barriers: []
```

(T7-1은 비노출·읽기 전용·별칭이라는 명시 불변식을 지므로 RISKY. T7-2는 설정 파일 1개와 확인 절차라 NONE. T7-2→T7-1 간선은 산출물 소비 — 등록이 가리키는 모듈을 T7-1이 만든다.)

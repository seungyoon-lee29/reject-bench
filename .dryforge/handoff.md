## 프로젝트 정체성

Reject Bench는 프로젝트 고유 가드를 여러 AI 코딩 세션에서 운영하는 1인 개발자가, 가드 발동 증거를 바탕으로 가드를 유지·수정·제거하도록 돕는 개인 도구 실험이다.

핵심은 거부 횟수나 범용 AI 코드 품질이 아니라 **가드 수명주기 결정**이다.

## 사용자와 현재 대안

- 사용자: 같은 저장소에서 같은 지속형 가드를 여러 세션에 걸쳐 운영하는 1인 개발자
- 현재 대안: 발동 순간 기억으로 수정·무시하고, 필요하면 흩어진 오류 로그를 수동 검색
- 가치 조건: 결정 가능성, 근거 복원 노력, 결정 확신 중 하나 이상이 개선되어야 함
- 채택 조건: 세션 뒤 검토 부담이 얻는 가치보다 작아야 함

## 핵심 흐름

`GuardSpec → GuardEvent → PolicyVerdict → UtilityReview → GuardDecision → Report`

- GuardSpec은 사건 전에 버전 고정된 정책 맥락이다.
- GuardEvent는 자연 운영과 시험 출처를 생성 시점부터 구분한다.
- PolicyVerdict는 LLM이 명시 정책 일치성만 판단한 결과다.
- UtilityReview는 사용자가 실제 유용성을 판단한 결과다.
- GuardDecision은 여러 세션 근거에 연결된 `keep | modify | remove`다.

## 하드 경계

- 코딩 중 검토로 흐름을 끊지 않는다.
- 시험 사건을 운영 가치 증거로 쓰지 않는다.
- LLM 정책 판정과 사용자 유용성 판단을 한 오탐률로 합치지 않는다.
- 분모 0은 성공이 아니라 미검증이다.
- 적재 시점부터 비밀 평문을 저장하지 않는다.
- 판정 과정에서 임의 코드를 실행하지 않는다.
- 외부 사용자 실제 사용 전 팀·시장·생산성으로 일반화하지 않는다.

## 구현 Foundation

- 언어: Python 유지
- 저장: 로컬 append 레코드, 원자 append와 파일 락
- 테스트: pytest, 임시 디렉터리만 사용
- 판정 API: 환경변수로만 인증, 호출 비용이 생기기 전 승인 상태 확인
- 사용자 표면: v1은 최소 CLI와 정적 로컬 보고서
- 공개 원장·대시보드·MCP·CI·SaaS: 범위 밖

## 관찰과 외부 검증

기술 E2E는 시험 사건으로 완료할 수 있다. 사용자 가치 검증은 같은 가드의 여러 세션 자연 운영 사건이 있어야만 시작된다. 내부 흐름과 수명주기 결정 1건을 끝낸 뒤에만 독립 사용자를 대상으로 외부 검증을 고려한다.

## 주장 문구

허용되는 최대 문구:

> 내 저장소에서 사라지던 가드 발동을 증거 기반 가드 결정으로 바꾸는 개인 도구 실험.

이보다 넓은 주장은 별도 실증 없이는 금지한다.

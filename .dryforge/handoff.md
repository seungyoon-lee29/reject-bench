## 실행 모양

**선행 절차 하나 + 완전 순차 8태스크.**

- **선행 절차 — 기준선 측정**(빌드 아님, plan 태스크 아님): 기록된 `block-dangerous-git` 자기차단 2건을 transcript+git 복원으로 측정한다. transcript가 2026-08-10~09-01 28개 연속 잔존이라 지금 가능하고 미룰수록 소멸 위험만 커진다. **이 절차를 마치기 전에는 E0 이하 어느 태스크도 시작하지 않는다.**
- 태스크: E0→E1→E2→E3→E4→E5→E6→E7. 그래프는 논리 의존(`depends`)과 순서 제약(`after`)을 구분해 표기한다 — plan 참조.
- 스캐폴드 없음(기존 프로젝트, 새 의존성 없음). 전체 게이트는 `uv run pytest` 하나(연속성 회귀 포함).
- 완료 게이트에 E3 임시 store 실기동 왕복 1건, E0·E4 읽기 조회 캡처(목적지 `docs/배선-목록.md`), `diff CLAUDE.md AGENTS.md` exit 0.

## 하드 게이트 (코드에서 유도할 수 없는 비협상 제약)

1. **기록 no-throw 봉투.** E1·E2의 어떤 변경도 예외를 기록 경로 밖으로 새게 하면 안 된다. 기록 실패가 가드 발동 결과를 바꾸면 안 된다는 v1 최우선 계약의 안쪽이다. **더해서**: 신규 로직의 예외는 `assemble_event` 안에서 닫아 현행 동작으로 폴백하고 GuardEvent를 정상 기록한다 — 봉투 밖으로 나가면 `recorder.py:286-299`가 LossRecord 강등을 부른다.
2. **테스트는 임시 store만.** 운영 `data/`에 닿으면 conftest autouse 게이트가 하드 실패시킨다 — 게이트를 끄거나 완화하지 않는다. 네트워크 금지.
3. **기준선이 선행이므로 조회 금지는 측정 완료로 해제된다.** 측정 전에는 `guard_evidence`·`get_report` 호출 금지(등록 확인 기동·`list_guards`만 허용). 측정 후에도 **E3 검증·실기동은 테스트 격리 목적으로 임시 store로만** 한다 — `.mcp.json` 등록 서버·인자 없는 기동은 조용히 운영 store를 읽고, `REJECTBENCH_STORE` env는 기록기 전용이라 서버에 통하지 않는다. 완성된 명령은 이 한 줄이다:

   ```
   PYTHONPATH=/Users/ian/workspace/reject-bench /Users/ian/.local/bin/uv run --project /Users/ian/workspace/reject-bench python -m rejectbench.mcp_server --store <임시 경로>
   ```

   `PYTHONPATH` 접두를 빼지 말 것 — `pyproject.toml:15`가 `package = false`라 저장소 밖 cwd에서는 `uv run --project`만으로 `ModuleNotFoundError`가 난다(C0 근본원인과 같은 이유).
4. **양성 대조 없이 E3 완료 선언 금지.** UUID 문법 준수 ID를 일반 단어 속에 파묻은 픽스처로 도구 3종+오류 경로에서 원문 0회를 확인해야 한다. 깨끗한 픽스처의 깨끗한 출력은 증거가 아니다. 기존 002 양성 대조도 전부 유지·통과.
5. **전역 설정 편집은 스냅샷·롤백을 거친다.** E0·E4 모두 해당한다: 편집 직전 스냅샷(사용자 소유 `.bak-*`와 **다른 이름**) → 임시 파일에 쓰고 **JSON 파싱 성공 확인 후** 교체 → 검증 실패 시 스냅샷에서 복원. 대상이 git 밖이라 되돌릴 다른 수단이 없다.
6. **전역 설정은 collect.py 항목 4건만.** `~/.claude/settings.json`의 다른 훅(알림·핸드오프 게이트·타 도구·v7 래퍼)은 불변. 사용자 소유 백업(`.claude/settings.json.bak-*`, `.codex/config.toml.bak-*`)은 스테이징·수정·삭제 금지.
7. **관찰 프로토콜은 append만.** E5는 "변경 기록" 절에 덧붙이기만 한다. 기존 본문 한 줄도 수정·삭제하지 않는다.
8. **새 행동은 red→green.** 실패 테스트 확인 후 구현(구현층 테스트 규칙).
9. **이 저장소는 `.dryforge/` 계약 문서 3종을 git 추적한다**(`.gitignore`가 `worktrees/`·`status.json`만 제외). 기본 gitignore 규칙으로 추적을 풀지 말 것.

## 함정 (실행 중 걸리기 쉬운 것)

- **전역 가드 자기차단이 곧 운영 사건이다.** 위험 패턴 텍스트가 픽스처·문서에 들어갈 때 heredoc/echo로 쓰면 전역 가드가 명령 전문 매칭으로 차단하고, **그 발동이 실제 operation 사건으로 기록된다**(이 작업 세션 자체가 관측 범위다). 파일 도구(Write/Edit)로 쓸 것. 시험·강제 발동이 필요하면 반드시 `REJECTBENCH_TEST_SESSION` 아래에서.
- **E0 이후 작업 트리 코드가 전역에서 해석된다.** `pyproject.toml:15`가 `package = false`라 훅은 설치본이 아니라 작업 트리를 import한다. E1·E2 편집 중 중간 저장 상태가 import 불가면 **모든 저장소의 모든 Bash 호출**에서 가드가 죽고 그 사이 발동은 기록되지 않는다 — 관측창 한복판에서. 각 체크박스 뒤 import 스모크가 이 위험을 받는다.
- E2 형식 기본값(8~128자, `[A-Za-z0-9_-]`)은 튜닝 가능하지만 **하이픈이 문자집합에 있어야 한다** — Claude Code 세션 ID가 UUID(하이픈 포함)다. 다만 **E3 자격은 이 술어가 아니라 UUID 문법으로 분리됐으므로**(D4) 술어를 튜닝해도 E3 보장 범위는 바뀌지 않는다. 하이픈 경고는 E2 진단값의 의미를 지키기 위한 것이고, "보장 공집합" 최악 시나리오는 구조적으로 제거됐다.
- E3 분류는 **출력 시점 모양 기준**이다. E2의 저장 필드로 분류하면 과거 레코드(필드 부재)가 보장 밖으로 밀려난다 — 사용자가 명시적으로 "과거 기록도 모양만 맞으면 자동 포함"을 확정했다.
- 자리표시 `harness:unknown`은 준수 부류가 아니다. 부분문자열 매칭에 넣으면 응답 속 일반 단어 `unknown`이 훼손된다. 같은 이유로 날짜꼴 값(`2026-09-01`)이 준수로 분류되면 안 된다 — 자격을 UUID 문법으로 좁힌 이유다.
- 출력 경계의 기존 계약 — 긴 needle 우선, 별칭 재치환 방지, 홈 치환 전 별칭화, 오류 경로 포함 단일 경계 통과 — 는 확장 후에도 그대로여야 한다. mcp 2.x SDK 함정(ToolError 접두, `fastmcp` 개명, 예외 유출 시 stderr traceback)은 002 승계.
- 배선·등록 명령은 `/Users/ian/.local/bin/uv run --project /Users/ian/workspace/reject-bench …` 절대 경로 관례. 실행 디렉터리를 가정하지 말 것.
- E4에서 pyproject의 `testpaths`·`pythonpath`(`hooks` 포함)는 그대로 둔다 — 연속성 테스트가 계속 게이트 안에서 돈다.
- 기존 저장 레코드(002 완료 시점 기준 5건 — 이후 자연 발동으로 늘었을 수 있음)는 한 건도 재작성하지 않는다. E2 필드는 새 기록부터만 채워진다.
- **E2의 파서 함정**: 현행 `record_from_json`은 키 집합 완전 일치를 강제한다. `_expected_keys`는 `_PARSERS[record_type]`별로 계산되므로 새 필드를 필수로만 더하면 **`guard_event` 줄만** 손상 줄로 떨어진다(다른 6종은 멀쩡하다). 실제 피해는 "등록부 조회 실패"가 아니라 **운영 지표의 분모·사건 목록·검토 큐에서 사건이 통째로 사라지고 손상 줄 수만 늘어나는 것**이다 — 조용하고, 보고서상 사건 0건과 구별하기 어렵다. 7.0 구형(필드 부재=`unchecked`) 수용을 반드시 함께 구현하고 구형 파싱 red 테스트로 고정할 것(spec §4.8). 완화는 `guard_event`의 `session_id_format` **하나**로 한정하고, 다른 필드 누락이 여전히 손상 줄임을 red 테스트로 고정한다.
- **정본 갱신은 E6 태스크다(마무리 관례가 아니다)**: `rejectbench/AGENTS.md`의 비노출 불변식 서술(`:27` "단어에 붙은 동일 부분문자열은 보존", `:29` "임의 부분문자열까지 0회를 보장하려면 먼저 세션 ID 문법을 적재 계약에 추가해야 한다")과 루트 `CLAUDE.md`/`AGENTS.md` 비협상 ⑥은 E3 뒤 낡는다. E6가 plan 체크박스로 갱신하고 `diff CLAUDE.md AGENTS.md` exit 0으로 판정한다 — 완료 게이트의 "spec 요구 전부 태스크로 소급 가능"이 이 태스크로 성립한다.
- **E7 파티션의 합을 검산으로 쓰지 말 것.** 사건 단위 지표의 원수는 두 벌의 합이 전체와 같지만, 결정 완료율은 가드 단위(서로 다른 2세션 규칙)라 한 가드가 전체에서는 판정 가능이면서 어느 파티션에서도 판정 불가일 수 있다.
- **E5는 8건이다.** 개정 전 3건에서 늘었고, 그중 ⑥(본문 vs 변경 기록 승자 규칙)은 본문에 넣으면 하드 게이트 7과 충돌하므로 **변경 기록 안에** 둔다.

## 문서에 담기지 않은 저작 시점 의도

- **판정 첫 과금 호출 승인 기록**: 2026-09-01 사용자 명시 승인("판정 첫 과금 호출은 승인"). 실행은 이 빌드 밖 — 기준선·검토 큐 처리 시점에 `--approve-billing`과 함께, 이 승인을 근거로 한다. 교정 검사 후 대기 2건 판정이 첫 호출이다.
- **후속 일정(빌드 아님)**: 관측창 4주 종료 판정은 2026-09-26경. 기준선 측정 시한 2026-09-07은 **선행 수행으로 무의미해졌다**. reply-gate 배포는 진행하지 않는다(완성 — 사용자 확인). 대화 기록 소멸 시 기준선은 다음 자연 사건으로 이월(E5①이 프로토콜에 추기).
- **다음 주기 후보**: MCP 조회 서버 전역 등록 — 기준선 측정 뒤에만 결정(002 저작 의도 승계).
- **"형식 규칙+가림 확장"은 사용자가 추천을 수용해 택했고, 위치(스팬) 기록안은 기각됐다.** 구현이 부담돼도 스팬으로 확장하지 말 것. 가림 확장을 빼고 형식 규칙만 남기는 축소도 계약 위반이다.
- **E4 완전 퇴역은 일반 텔레메트리 수집 종료를 받아들인 사용자 결정이다.** "혹시 몰라 남기자"로 파일·배선을 되살리지 말 것. 수집 데이터(`data/events.jsonl`)는 보존한다.
- **E7은 권고안과 다른 선택이다.** 권고는 "종료 보고 시점 사람 판정"(코드 변경 0)이었으나 사용자가 자동 계산을 택했다 — 손으로 세는 오류를 없애는 쪽. 되돌리려면 사용자 결정이 필요하다.
- **독립 감사·적대 리뷰 반영**: 이 설계는 인터뷰 후 독립 감사의 7개 지적(4주 시계, 관측 무대, 형식 규칙의 대상 값, 과거 레코드 처우, 기준선 시한, 관측 중 기구 변경, 범위 번들)을 닫은 뒤, 2026-09-01 적대 리뷰 finding 27건(수용 25·축소 2·기각 0)을 다시 반영한 결과다. 재발 방지 근거가 필요하면 [`../docs/운영경험개선-증분-결정기록.md`](../docs/운영경험개선-증분-결정기록.md)를 참조.

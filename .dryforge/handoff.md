## 하드 게이트 (불가침)

1. **v0 자산 불변**: 읽기만. 준비 baseline 접두 해시(자기 캡처 금지). 로컬 검사에 원본↔원장 정합(재발행·tombstone 대응 포함)
2. **공개 = push, 확인은 push 앞**(체크리스트: 시크릿·PII·민감정보·큐레이션·제외 기록·미결 6). 브랜치 전체만. **증거 구간 = push 이후, push 후 재작성 금지**(예외: 사고 대응+정정 기록). **판정 전 앵커 push가 런북 계약**(J-③) — push 없이 수행된 첫 판정은 실질 보증 미계상(spec §0)
3. **선커밋 순서(조상 관계)**: 선커밋 ⊂ **최초 앵커** ⊂ 판정. 적용=독립 첫 판정. **재판정·사용자 번복 모두 선행 `독립 첫 판정` 필수**(CLI 거부+pytest — 유형 선언 우회 차단). 재판정은 명시 면제+병기. post-hoc 표기, 대외 서사 4종 문구 검사
4. **비밀 하한**: 선별 벤더링+5종, 축소 금지. 마스킹은 적재 시점. 세션 id 금지. **사고 대응은 비밀·PII·사용자 지정 민감정보까지** — push 전=이력 정리 기본(tombstone 금지), push 후=tombstone+정정 기록, 원본·백업도 동일 정리(spec 3.5). 하한은 원장·원본 불변보다 우선
5. **기록기 비블로킹**: 흔적(분리 위치·원문 금지) → 런북 ①·T6 ⓪이 유실 기록 갱신 → 집계 병기
6. **인과 주장 금지** + 고지 5항 전부
7. **범위 봉인**: 검증 에이전트·벤치·대시보드·MCP·reply-gate 수정·공개 시점 강제·재작성/push 시점 탐지·CI 수집은 안 만든다
8. **검증 게이트**: pytest(순서 검사·선행 규칙 포함) + 로컬 검사 + E2E(판정 레코드+**실데이터 검사 리포트** 존재) + §1 성립선 판정 + 문구 검사. 테스트는 실스토어에 쓰지 않는다

## 문서에 담기지 않은 제작 중 의도

- **왜 "형식이 계약"인가**: 실물 2건이 훅 밖(로컬 스크립트)에서 나왔다. 수집 배선은 로컬 전제(CI 미수집 — 고지)
- **왜 증거 구간을 push 이후로 좁혔나**: 로컬 이력은 재작성 가능. 확장 주장하면 그 과장이 공격점 — 좁혀 말하는 것이 방어
- **왜 판정 전 앵커 push인가(v6)**: push되지 않은 앵커는 "공개 앵커"가 아니다 — push 간격 안에서는 기준→원장→판정을 조상 순서로 소급 제작해도 구분 불가능하고, 그 구간의 실질 보증 건수는 장식이 된다. 판정 전에 앵커를 push하면 앵커가 재작성 금지 구간(증거 구간)에 들어간 뒤 판정이 생긴다 — push 여부·시점이 자기 보고라는 잔여 한계는 고지. **기준·규칙 개정을 런북 ⑥ 이후로 미루는 것도 같은 이유다**(발생↔앵커 사이 개정 = HARKing 창)
- **왜 원장인가**: 발생 시각은 자기 보고 — 원장 최초 append 커밋이 앵커가 되어 조상 검사가 성립. 재발행은 원 id·원 앵커 참조를 승계(검사는 최초 앵커 기준 — 사고 대응이 검사를 깨지 않게)
- **왜 검사 대상이 "독립 첫 판정"뿐인가**: 재판정은 정의상 기준이 앵커보다 늦다 — 공개 면제+병기가 유일하게 정합적. **면제 악용은 선행 첫 판정 필수 규칙이 막는다 — v6에서 사용자 번복에도 같은 규칙을 걸었다**(번복-first로 독립 판정 없이 "판정 완료건"을 만드는 경로 차단)
- **왜 판정 가능성이 등록부 등재 기준인가(v6)**: 판정 입력에 가드 정의가 필수인데 정의의 소재가 등록부다 — "형식 준수 여부" 기준은 미등록 정형이라는 무명 계급을 만들었고, 등록 회피가 형식 회피와 동형의 분모 조절 채널이었다. 미등록 거부는 가드 식별자별로 병기해 채널을 가시화한다(차단은 못 한다 — 고지)
- **왜 소급 첫 판정이 post-hoc인가**: 관찰 후 기준 작성은 선등록이 아니다(HARKing). 표기는 방어선
- **왜 실행 설정까지 선커밋하나**: 모델·파라미터 자유면 판정값은 샘플링 표본. 고정이 게이밍 비용을 올린다
- **왜 방어 지시가 가드 정의까지 불신하나(v6)**: 판정 입력 중 사유·가드 정의 둘 다 피판정자 작성 텍스트다 — 사유만 불신하면 정의 쪽(독스트링·주석)이 조향 채널로 승격된다. 정의는 "무엇을 막는가"의 사실 근거로만
- **왜 오탐 장면이 공개 기본값인가**: 승인제만으로는 재량 삭제 가능. 제외는 사용자 지정만+기록 공개+원장 사고 대응 연동(장면만 빼기 금지). 큐 탈락·중복도 동일 기록 요건 — 단 내용 검증은 불가(참조 대상 비공개), 과대 표현 금지
- **왜 참고 오탐률이 동급 표기인가(v6)**: 최신 유효값은 기준 개정+재판정으로 뒤집을 수 있는, 게이밍 내성이 낮은 수치다 — 내성 높은 수치(독립 첫 판정 기준)를 각주로 격하하면 역전이다. 나란히 낸다
- **왜 기각률을 안 재나**: 분자·분모 실측 무효. 오탐률이 대표 — 한계는 고지
- **오탐률 공식(분모=판정 완료건)은 사용자 선택** — 미결 1 확인 대상

# Project Foundation

> **실행 대상이 아닌 컨텍스트** — 미래 몫의 이번 판 구현은 범위 위반.

## 1. 프로젝트 정체성

**Reject Bench** — AI가 짠 코드를 기각하는 검증 도구 + 개발 과정의 승인/기각 공개 기록.

- **축은 현업 문제**: "기각 근거는 프로젝트 안에 있는데 검증 도구에도 로그에도 없다." 작성자 본인의 Claude Code 세션 실측으로 푼다. 채용 증명은 결과로 따라온다.
- **설계 기준은 정직성 구조**: 선커밋+앵커 push(조상 관계 — 조건·한계 spec §0) · 제3자 재현(추적 산출물 재계산 — 한계 고지) · 불리해도 공개(집합 내 비선별은 구조, 시점 재량은 고지).
- **역할 제약 (3카드의 C)**: "AI 산출물 검증 능력". 요구역량 6·8·9, MCP 서버 1개 전담(미래 몫). MCP·하네스 공고(블록에스·이너버즈)에 첫 카드. 3초 데모·이력서 포맷.
- **사용자·규모**: 1인 개발자. 데이터 원천 Reply-Gate(`~/workspace/reply-gate` — 공개 GitHub, 확인됨. **단 그 저장소 이력은 이 계약의 force-push 금지 밖** — 등록 시점 정의 해시가 완화). 독자는 채용 심사자·개발자.
- **하드 제약**: 임의 코드 실행 금지(정의는 spec 불변식 7) · 비밀 평문 금지 · v0 원본성 불변 · 일정 유동·품질 우선(**발췌만 시한 하드**).
- 근거: `docs/문제정의/00~05`, `기획-입력.md`(미결 1·6), `~/workspace/포지션찾기/` 정본 2종.

## 2. 도메인 모델

### 용어

- **가드**: 프로젝트에 심는 검증 코드/규칙. 위치 자유(수집은 로컬). **가드의 거부**가 1급 신호(실측: permission 기각 Edit/Write 0건, 유의미 거부 2건 전부 가드)
- **거부**: 가드가 형식으로 막은 사건. 판정 가능성은 등록부 등재 기준(미등록·미상은 병기)
- **원장**: 공개본 전수 추적 append 파일. **최초 append 커밋 = 앵커, 증거력은 push부터**
- **오탐**: 판정에서 "그 거부는 틀렸다". 선커밋 4종+보조 스키마
- **소급 재구성**: v0 로그의 과거 거부 재기록. 판정은 post-hoc
- **관측 개입**: 고지 5항 상시 공개

### 엔티티와 수명주기

| 엔티티 | 생성 | 변화 | 불변 |
|---|---|---|---|
| 가드 | 심는 커밋 | 수정도 커밋 | 제거돼도 레코드 잔존 |
| 거부 레코드(원본) | 기록기 적재(`data/`, 마스킹본, 고유 id) | 불변(append) | 예외: 사고 정리(spec 3.5) |
| 원장 항목 | 동기화 append(추적, 공개 필터) — **판정 전 push** | 불변 | 최초 append=앵커. 예외: 사고 대응(원 id·원 앵커 참조 승계) |
| 가드 식별자 | 등록부(식별자·도입 커밋·별칭·정의 링크·**정의 해시**·버그 기록) | 개명은 별칭 | 재사용 금지, 미등록은 식별자별 병기 |

| 선커밋 4종+보조 스키마 | 판정 전 별도 커밋(메인 직접) | 변경도 커밋(개정은 런북 ⑥ 이후) — 레코드가 버전 참조 | — |
| 장면/집계 | 생성기(제외 모드 포함) | 재생성 가능 | 선별·병기 규칙(spec 3.5) |

### 상속하는 사실 — v0 결함

## 4. 미래 몫 (범위 밖 — 호환만)

우선순위(확정): **거부 장면+오탐률(불가침) > 검증 에이전트 > 대시보드 > 메타 평가**.

- **가드 심기**: 완료 직후 사용자 — 어댑터 설치 선행. 등록부 등록(정의 해시 포함)+reply-gate push(미결 7)
- **검증 에이전트**: diff→accept/reject+근거. 샌드박스, 본인 레포 한정
- **메타 평가 벤치**: gold set·채점 선등록, 비교군 3종. 져도 공개. 빈 자리는 **중립 운영·선등록·제3자 재현**(`02-리서치-도구지형.md` §13)
- **대시보드 / MCP 서버**(가드 계층 자체) / **사유 분류**(귀납) / **전후 비교**(등록부 기반)
- **CI 수집 / 공개 시점 강제 / 재작성·push 시점 탐지**: 이번 판은 고지로 대체
- **백업**: `data/` 주기 백업 권고
- **제출 리듬**: 로그 한 달(9월 초), 블로그 1~2편

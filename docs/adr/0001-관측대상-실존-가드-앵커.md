# 관측 대상을 실존 가드 2종으로 앵커하고, 기록기를 관측 무대보다 먼저 세운다

v7의 사용자 가치 조건("같은 가드의 다세션 자연 발동")은 기존 실측에서 충족 가드가 0개였다 — 관측 대상을 정하지 않으면 분모가 영원히 생기지 않는다(적대리뷰 C4). 한편 실존 지속형 가드는 정확히 2개(전역 `~/.claude/hooks/block-dangerous-git.sh`, reply-gate `.claude/hooks/protect-live-reports.sh`)이고, 자연 발동이 가장 확실하게 기대되는 실작업은 reply-gate 배포 잔여 작업이다. 그래서 2026-08-28 인터뷰(07 Q1·Q2)에서 결정했다: **v1 관측 대상은 이 실존 가드 2종으로 고정하고, 기록 저장은 reject-bench 중앙으로 하며, 기록기(T1~T3)와 관찰 프로토콜을 먼저 세운 뒤에야 reply-gate 배포 작업(1차 관측 무대)을 시작한다.** 두 저장소는 병합하지 않는다 — 결합되는 것은 데이터 흐름(발동 → 중앙 기록)과 포트폴리오 서사뿐이다.

## Considered Options

- **관측용 가드를 새로 설계** — 표본은 늘겠지만 "관측하려고 가드를 만들었다"는 순환(B-F-27)이 강해지고 새 가드의 자연 발동은 더 불확실하다. 기각.
- **대상 확정을 T3 직전까지 유보** — 관측창을 데이터를 본 뒤 고르는 사후 선택 위험(C5)이 남는다. 기각.
- **reply-gate 배포를 먼저 마감** — 메인 카드가 빨리 서지만 그 세션들의 가드 발동이 기록기 부재로 다시 유실된다. v7이 풀려는 문제를 스스로 재발시키는 순서라 기각.

## Consequences

- reply-gate 배포가 T1~T3 완성만큼 늦어진다. 대신 배포 세션 전체가 증거로 남는다.
- `block-dangerous-git.sh`는 heredoc 오차단 이력 2회가 이미 있어, 증거 기반 `modify` 결정 1건이 현실적인 첫 수명주기 결정 후보다.
- 관측이 작성자 본인의 프로젝트에 한정되므로 일반화 주장 불가(주장 상한 유지)와 1인 자기측정 한계 명시가 계속 필요하다.
- 전역 가드 특성상 다른 저장소 세션의 발동도 관측 범위에 들어온다 — 사건의 `project` 필드가 저장소를 구분한다.

## Supersede 기록 (2026-09-02)

**부분 supersede** — 003 주기 E5⑧, 정본은 [`../관찰-프로토콜.md`](../관찰-프로토콜.md)의 "변경 기록" ③·⑤·⑧이다. 위 본문은 결정 당시의 근거로 그대로 보존한다.

- **대체된 것**: "1차 관측 무대 = reply-gate 배포 잔여 작업"과 그 귀결 "배포 세션 전체가 증거로 남는다". reply-gate는 완성 상태라 배포 작업이 진행되지 않고(2026-09-01 사용자 확인), 자연 발동 기대는 전역 가드 `block-dangerous-git` 중심이 되며 `protect-live-reports`의 기대 발동은 0에 수렴한다. 판정 가능 가드 성립은 사실상 `block-dangerous-git` 단독에 의존한다.
- **유지된 것**: 관측 대상을 실존 가드 2종으로 앵커, 기록기·프로토콜을 무대보다 먼저 세움, 중앙 저장, 두 저장소 비병합. "관측하려고 가드를 만들었다"는 순환의 기각은 유지를 넘어 **강화**됐다 — 도구개발 세션의 자기차단을 별도 파티션으로 가르고 종료 조건을 그-외 파티션으로 판정하는 규칙(변경 기록 ⑤)의 근거가 이 기각이다.
- 프로토콜(변경 기록 포함)과 이 ADR이 충돌하면 프로토콜이 이긴다.

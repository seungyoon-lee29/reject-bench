# 자연 운영 관찰 프로토콜 (선등록)

작성 2026-08-29, 관측창 오픈 전 고정. 이 문서는 spec §7 "운영 검증"이 요구하는 선등록 산출물이다. **고정 후 변경은 덮어쓰지 않고 사유 있는 추기(append) 수정으로만 한다** — 아래 "변경 기록" 절에 일자·사유·변경 내용을 덧붙인다.

## 관측 범위

- **관측 대상 가드 2종** (등록부 v1, `data/v7/records.jsonl`):
  - `block-dangerous-git` v1 — 전역, `~/.claude/hooks/block-dangerous-git.sh`
  - `protect-live-reports` v1 — reply-gate, `.claude/hooks/protect-live-reports.sh`
- **런타임 범위: Claude Code 세션만.** Codex 세션은 v1 관측 범위 밖이다(2026-08-29 사용자 결정 — 페이로드 스키마 미확인). reply-gate 작업을 Codex로 수행하면 그 발동은 관측되지 않으며, 이 공백은 보고서에 명시한다.
- **저장소 범위**: 전역 가드는 Claude Code가 도는 모든 저장소 세션, reply-gate 가드는 reply-gate 저장소 세션.
- 1차 관측 무대는 reply-gate 배포 잔여 작업이다(ADR 0001). 배포 작업은 관측창 오픈 후에만 시작한다.

## 종료 조건 (2026-08-29 사용자 결정)

관측창 오픈 시각부터 **4주 경과** 또는 **판정 가능 가드 1개 성립**(같은 가드의 서로 다른 둘 이상 `operation` 세션 사건 + 그 사건들의 정책 판정·유용성 검토 모두 확정값) 중 **먼저 오는 시점**에 평가한다.

- 조건 충족 → O2(수명주기 결정·반증 평가)로 진행.
- 4주 시점까지 미충족 → **"운영 빈도 미검증"을 그대로 기록**하고 종료한다. 표본을 채우기 위한 강제 발동은 하지 않는다.
- 종료 시 **기술 상태(완료/미완)와 가치 상태(검증/미검증/가치 실패/채택 실패)를 각각 선언**한다. 두 축을 합쳐 말하지 않는다.

## 평가 양식 (선등록 — 사건 검토·결정 시점마다 기록)

1. **의사결정 시간**: 이 사건(또는 이 가드 결정)을 판단하는 데 걸린 시간은 몇 분인가? (숫자)
2. **근거 복원 노력**: 발동 당시 맥락을 다시 확보하는 데 든 노력은? (1=즉시 확보 ~ 5=복원 실패 수준, + 한 줄 서술)
3. **결정 확신**: 이 판단/결정이 옳다는 확신은? (1=추측 ~ 5=확실, + 근거 한 줄)

가치 개선 판정은 이 세 문항의 기준선 대비 변화로만 한다. 사후에 문항을 바꿔 유리하게 읽지 않는다.

## 기준선 측정 절차 (첫 자연 사건 1회)

첫 자연 `operation` 사건이 관측되면, **도구 보고서를 열람하기 전에**:

1. transcript와 git 기록만으로 발동 맥락(어떤 가드·무슨 행동·왜 차단)을 복원한다.
2. 소요 시간(분)과 복원도(확보한 판정 필수 정보 / 필요 정보)를 기록한다.
3. 그 다음 도구 경로(보고서·레코드)로 같은 복원을 반복해 시간·복원도를 기록한다.

이 1회 측정이 위 평가 양식의 비교 기준선이다.

## 표본 규율

- 시험·강제 발동은 반드시 `REJECTBENCH_TEST_SESSION` 플래그 아래에서만 한다. 플래그 없는 발동은 `operation`으로 기록된다.
- 출처는 운영자 본인 선언 기반이며 독립 검증 신호가 없다 — 보고서에 이 한계를 병기한다.
- 관측 도중 새 가드를 등록하면 그 사건은 별도 표기하고 기존 지표와 섞지 않는다.
- 단측 증거 한계: 발동한 사건만 관측되며, 가드가 막지 못한 실패는 관측 밖이다.

- **2026-09-02 ⑧ ADR 0001 supersede** — 사유: ③이 ADR의 무대 전제를 바꿨다(결정기록 C3). [`adr/0001-관측대상-실존-가드-앵커.md`](adr/0001-관측대상-실존-가드-앵커.md)는 **부분 supersede**다. 대체되는 부분: "1차 관측 무대 = reply-gate 배포 잔여 작업"과 그 귀결("배포 세션 전체가 증거로 남는다"). 유지되는 부분: 관측 대상을 실존 가드 2종으로 앵커, 기록기·프로토콜 선행, 중앙 저장, 저장소 비병합, "관측하려고 가드를 만들었다"는 순환의 기각 — 마지막 것은 ⑤의 근거로 오히려 강화됐다. ADR 파일에는 상태 표기와 이 항목으로의 참조만 덧붙이고 본문은 보존한다(왜 그렇게 정했는지의 기록). 프로토콜 본문·변경 기록과 ADR이 충돌하면 프로토콜이 이긴다.
- **2026-09-02 ⑨ 대조 판정의 실행 순서 규칙** — 사유: 확정 판정은 사건별 최신 레코드라 두 모델을 대조하면 **나중에 돌린 모델이 지표를 정한다**(2026-09-01 대조 6건에서 gpt-5-mini를 나중에 돌려 정책 불일치율 0/4가 됐고, 순서를 뒤집으면 4/6이었다 — [`기준선-측정.md`](기준선-측정.md) 부록). 2026-09-02 사용자 결정: **기본 모델(`judge` 기본 설정, 현재 gpt-4.1-mini)의 판정이 항상 마지막**이다. 대조 모델 rejudge를 먼저, 기본 모델 rejudge를 마지막에 돌려 확정값이 항상 기본 모델이 되게 한다. **소급 적용하지 않는다** — 지난 6건의 확정값은 gpt-5-mini로 남기고, O2의 판정기 신뢰도 판단에서 두 모델 값을 같이 본다. 판정기 신뢰도의 추가 임계는 선등록하지 않는다(이미 결과를 본 뒤라 사후 등록이 된다). 사건 정의·출처 규칙·평가 양식·종료 조건 불변.

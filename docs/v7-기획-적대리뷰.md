> 여러 AI 코딩 세션에 걸쳐 지속형 가드를 운영하는 1인 개발자가, 가드 발동 사건을 발생 당시 버전으로 고정된 가드 맥락과 함께 비블로킹으로 기록하고, 세션 뒤 독립 LLM의 정책 일치성 판정과 사용자 본인의 유용성 검토를 분리 수행해, 그 증거로 가드별 `keep | modify | remove` 수명주기 결정을 내리게 하는 개인 도구 실험.

리뷰어 2명과 메인의 블라인드 요약이 사실상 동일 — 문서 가독성·목적 전달은 검증됨.

## Ⅰ. 교차 재현된 결함 (A·B 독립 일치, 다수는 메인까지 3자 일치 — 전부 원문 확인)

### 치명~중대

**C1. 성공 판정 설계가 통째로 비어 있다** 〔A-F1·F2·F11 + B-F-12 + 메인〕
- (a) "사용자 가치 검증"이 실제로는 **절차 완수**로 정의됨 — 자연 발동만 생기면 나머지 단계는 본인 행위만으로 항상 완수 가능. 관찰 종료 선언이 배타 4지선다라 "흐름 완료했으나 가치는 실패"를 표현할 수 없음 (`spec.md:21-23`, `spec.md:244-249`, `plan.md:140`).
- (b) "결정 가능성·근거 복원 노력·결정 확신 개선"과 "검토 부담 > 가치"를 판정할 **척도·기록 양식·기준선 측정이 전무** (`06:125-126`, `plan.md:135-136`). 05가 1순위 급소로 명명한 "자기가 자기를 측정한다"(05:24-30)의 통제 장치(선등록·재현·외부 baseline)를 공개 축과 함께 폐기하면서 개인 실험용 대체 장치를 넣지 않음 — 스스로 METR 43%p 자기평가 오차를 인용했던 것과 정면 충돌.
- (c) 06 내부 치환: 가설은 "**의사결정 시간**"(측정 가능, `06:33`)인데 가치 조건·반증·하류 전 문서는 "**결정 가능성**"(예/아니오 자기보고, `06:44,125`)으로 바뀜.

**C2. `origin=operation` 부여 규칙 부재** 〔A-F3 + B-F-18〕 — "명시적 test mode는 항상 test"(`spec.md:93`)만 있고 모드 부재 시 기본값이 operation인지 unknown인지, 강제/자연 판별 기준이 없음. 가치 검증 전체가 이 라벨에 걸려 있는데 결정 규칙이 미정의. `plan.md:123`의 출처 감사도 대조할 독립 신호가 없어 성립 불가.

**C3. 미등록 가드 발동의 처리 경로 부재 — v0 원죄 재발 구멍** 〔A-F4 + B-F-17 + 메인〕 — "존재하는 spec 참조 필수"(`spec.md:68-69`) + "무음 유실 금지"(`spec.md:92`)가 등록 전 가드 발동에서 동시 충족 불가. 발동 시 흐름(`spec.md:171-175`)에 참조 확인 실패 분기가 없음. 자기 실측 628행이 정확히 이 케이스(`docs/소급-발췌-매니페스트.md:17`)이고 구 spec의 "버전 불확실" 플래그는 대체물 없이 사라짐.

**C4. 가드 인벤토리·기저율·커버리지 부재 + 06이 불리한 실측을 누락** 〔B-F-20 + 메인 + A-F18 일부〕 — 기존 실측에서 다세션 자연 발동 조건을 충족한 가드는 **0개**(2건이 서로 다른 가드 각 1회, 그중 하나는 이미 제거 — `05:99`, 매니페스트:17). 06 "관찰된 사실"(`06:24-28`)은 이 빈도 실측을 뺐음. plan에 가드 목록화·전수 등록 태스크가 없고 T3는 가드 하나에만 배선(`plan.md:72`) — 나머지 가드 발동은 여전히 사라져 분모가 생길 수 없음.

**C5. T3 실배선이 O1 관찰 프로토콜 고정보다 먼저 켜짐** 〔A-F7 + B-F-24 + 메인〕 — T3~T6 기간에 쌓이는 실 operation 사건의 관찰창 포함 여부가 미정이고, 어느 쪽이든 데이터를 본 뒤의 사후 창 선택 = "관찰 시작 전 고정"(`06:122`) 자기 원칙 위반 (`plan.md:72` vs `plan.md:120`, `spec.md:244`).

**C6. 행동 뼈대·비밀 제거 ↔ LLM 판정 가능성의 구조적 긴장 미검토** 〔A-F6 + B-F-19〕 — 원문 미저장(`spec.md:161`) + 마스킹을 거친 뼈대만으로 명령·내용 조건부 정책의 위반 판정이 가능한지 분석 없음. v0가 이미 실증한 함정(`hooks/collect.py:27-28,36` — 24자+ 토큰 마스킹·200자 절단이 사유 파괴). `insufficient_context` 양산 시 두 축 설계가 공전하는데 "판정 불가율 과다 = 캡처 설계 실패"가 반증 조건(`06:124-127`)에 없음.

**C7. LLM 판정기 신뢰도 검증 장치 전무 + "독립" 미정의** 〔A-F14 + B-F-11〕 — 사건당 1회 호출, gold set·교차 판정·정확도 측정 없음. GuardSpec의 allow/block 예시를 판정기 교정에 쓰는 항목 없음. LLM-사용자 불일치율 분자에 "판정이 틀린 사건"과 "실제 괴리 사건"이 구분 불가로 섞임. 재판정 허용 경계도 "사유 명시" 한 줄뿐(`spec.md:119`).

**C8. 발동 사건만의 단측 증거 — false negative 사각 미선언** 〔A-F8 + B-F-14〕 — 놓치는 가드는 사건 0건 = 증거상 무결. `keep`이 "문제 없음"과 "가드가 죽어 있음"을 구분 못 하고, 정책 불일치율은 과잉 발동만 재는 반쪽 지표인데 한계 선언이 어느 문서에도 없음 (`06:9` 약속과 대비).

**C9. 대표 지표 분모 "판정 가능" 정의 부재·상충 + 분자⊄분모** 〔A-F10·F27 + B-F-01·F-13 + 메인〕 — `06:108`은 정의 없이 사용, `spec.md:196`(가드 단위, 판정 완료 불요구)과 `spec.md:146`(사건 단위 pending 제외)이 상반 독해를 만들며 정반대 유인(146 독해면 검토 방치가 완료율을 올림). 분자(`spec.md:194`)는 분모 부분집합 조건이 없어 발동 0건 가드의 remove 결정으로 100% 초과 가능. `00-계획:47`의 "분자·분모 모두 명시 완료" 선언은 과장.

**C10. 진단 지표의 `insufficient_context`/`uncertain` 분모 제외 규칙이 spec에서 탈락** 〔A-F12 + B-F-02 + 메인〕 — `06:118`·`기획-입력:57`은 제외 명시, 구현이 따를 `spec.md:200-202`는 "완료 사건"만 써서 문면대로면 포함 → 정책 불일치율이 계통적으로 낮게 산출.

### 보통

**C11. `content_hash` 해시 도메인 불일치·순환** 〔A-F13 + B-F-04〕 — `기획-입력:30`은 4개 의미 필드로 특정, `spec.md:55-64`는 "위 의미 필드"라 guard_id·version·created_at까지 포함되게 읽힘 → 시각 때문에 항상 해시가 달라져 T2 "의미 변경 시 새 버전 강제"(`plan.md:55`)를 내용 비교로 구현 불가.

**C12. "세션"의 조작적 정의 부재** 〔A-F16 + B-F-21 + 메인〕 — 가치 검증 관문 "둘 이상의 서로 다른 운영 세션"(`spec.md:145`)의 단위인 세션 경계(resume/compact 시 id 거동, 최소 간격, Claude Code↔Codex 간 비교)가 미정의. 이 저장소 자체가 compact 연속성 훅을 돌리므로 현실적 시나리오.

**C13. GuardSpec 텍스트 ↔ 실제 가드 코드의 드리프트 감지 부재** 〔A-F5 + B-F-26〕 — 코드를 고치고 등록을 잊으면 LLM은 실제 적용되지 않은 정책 문면으로 판정 — "버전 고정 맥락"(`06:27`)이 조용히 허구가 됨. `modify` 결정의 실제 코드 반영 확인 절차도 없음 (`spec.md:70-71,147`).

**C14. v0 배선 실체 미문서화 — Codex는 애초에 무관측, cutover 확인 절차 미정의** 〔A-F18 + B-F-28·F-32·F-33 + 메인〕 — 실측 확인: collect.py 배선은 사용자 전역 `~/.claude/settings.json:89,112,135,158`(4개 이벤트)에만 있고 프로젝트 설정·`.codex/config.toml`에는 없음. 즉 v0는 Claude Code 세션만 관측, Codex 발동은 원래부터 유실. 저장소 문서만 읽는 미래 세션은 "관측 공백 없음 확인 후 퇴역"(`plan.md:73`)의 대상 배선을 알 수 없음. 새 어댑터의 런타임 범위도 미정.

**C15. v7 창설 근거인 "재인터뷰"가 유일하게 무기록** 〔A-F17 + B-F-06〕 — 1차 사이클은 단계별 산출물이 있는데 2차 재인터뷰는 참조만 있고 문서가 없음 (`06:3`, `00-계획:26-32`). "리서치·심사 결과 미삭제"(`00-계획:55`) 원칙과 비대칭.

**C16. pending/uncertain/insufficient 상태 기계 혼선** 〔B-F-03 + A-F25〕 — `spec.md:130`이 기록된 검토값 `uncertain`을 "pending으로 남고"라 서술해 미처리 상태와 혼합. `06:118`이 요구한 "최장 대기 기간 표시"가 `spec.md:214`에서 건수만으로 축소, 보류 값의 해소 절차(재판정 트리거) 미정의.

**C17. "무음 유실 금지"가 최악 경로에서 이행 불가능한 절대 보장** 〔B-F-23 + A-F31〕 — 디스크·락 실패는 LossRecord 기록도 함께 실패시키는데 `spec.md:92`(절대)와 `spec.md:175`(최선 노력)의 계약 강도가 어긋나고 흔적의 대체 매체 지정이 없음.

**C18. `remove` 결정 이후 상태 미정의** 〔A-F28 + B-F-29〕 — 종결 상태가 없어 결정 뒤에도 발동이 계속되면 그 사건들의 지표·보고 처리, "결정 대비 실집행" 불일치 가시화가 없음 (`spec.md:132-148`).

### 경미

**C19. 소급 매니페스트의 죽은 참조** 〔A-F22 + B-F-07 + 메인〕 — "spec 3.6"·"spec 3.2 버전 불확실 플래그"(`docs/소급-발췌-매니페스트.md:1,5,17`)는 교체 전 v6 spec의 절 번호. 현행 spec의 3.2/3.6은 다른 내용이고 해당 플래그는 현행 spec에 없음. 역사 배너가 없어 현행 문서로 오독됨.

**C20. "T1" 라벨 충돌** 〔A-F23 + B-F-08 + 메인〕 — `06:3,146`의 T1(폐기된 v6 T1)과 `plan.md:39`의 T1(신규 도메인 계약)이 무설명 동거.

**C21. 완료 판정 불가능한 게이트 문구** 〔A-F29 + B-F-30 + 메인〕 — T2 "예시의 **최소 품질** 검증"(`plan.md:57`), T4 "비용 **승인 상태** 확인"(`plan.md:86`), "행동 뼈대"(`spec.md:83`)의 기준이 무정의.

**C22. enum 방향 함정 + 비배타 정의** 〔A-F34 + B-F-15〕 — 정상 발동의 라벨이 `policy_violation`이라 부호가 뒤집혀 읽히고, 예외(exceptions) 해당 행동은 "정책을 위반했다"와 "막아서는 안 됐다"가 동시 성립해 두 라벨이 상호 배타가 아님 (`spec.md:103`, `06:56-57`).

## 측정 설계

프로토콜 절차는 ① 도구 보고서 열람 **전에** transcript+git만으로 복원 → ② 소요·복원도 기록 → ③ 도구 경로로 같은 복원 반복이다. 이번에는 여기에 두 가지를 더했다.

- **블라인드 격리**: 측정을 주도한 세션의 컨텍스트에 이미 답이 들어 있었다(프로젝트 자동 메모리에 "git 가드레일 heredoc 차단 — 명령 문자열 전체를 매칭해서 문서 텍스트만으로도 Bash가 막힌다"가 적혀 있고, 이는 사실상 I3의 정답이다). 그래서 비도구 복원을 **독립 컨텍스트의 조사자 3인**에게 맡기고, 주도 세션은 도구 경로 결과가 나온 뒤에만 내용을 읽었다.
- **독립 대조 검증**: 조사자의 **자기보고 복원도를 믿지 않는다.** 검증자 3인이 항목별로 도구 사실과 대조해 `correct`만 세어 복원도를 재계산하고, "확신 있게 틀린 항목"(confidence ≥ 4인데 wrong)을 따로 뽑았다.

### 결정적 발견 — 조회 표면만으로는 5/6이 상한

두 도구 조사자가 **독립적으로 같은 결론**에 도달했다: `rejectbench-evidence` 조회 표면만으로 확보되는 것은 6항목 중 **5개(I1·I3·I5·I6, I2는 '종류'까지만)**이고, 나머지는 원리적으로 도달 불가다.

- **I4(의도)** — 스키마에 의도·맥락 필드가 없다. 비협상 ⑤(명령 전문·파일 전문 미저장)의 직접적 귀결이다.
- **I2의 명령 내용** — `reason`에 `<command omitted>`로 저장된다(`redact_command_echo`). 구조화 요약(`tool_name=Bash`, `command_verb=cd`, `heredoc=true`, `target_path`)까지만 나온다.
- **세션 별칭이 조인 키를 끊는다** — 이게 핵심이다. MCP 응답의 세션은 `S1`/`S2` 별칭이라, **조회 표면만 쥔 조사자는 어느 transcript 파일을 열어야 하는지 알 수 없다.** 별칭이 막은 것은 I5의 세션 id 값 하나가 아니라 **I4로 가는 다리 전체**다. 실제로 도구 조사자 둘 다 원본 `records.jsonl`에서 별칭 없는 `session_id`를 읽고서야 transcript로 피벗할 수 있었다.

홈 경로 `~` 치환은 복원을 전혀 방해하지 않았다(경로의 식별력이 그대로 남는다).

### 도구가 압도적인 항목 — I6(적용 정책 문면)

사건 시점 버전의 policy 전문 + `content_hash` + 구현물 일치(`enforcement.status=in_sync`) 판정이 **한 번의 응답**으로 나온다. 비도구 경로는 같은 결론에 훅 스크립트 mtime + 패턴 8개 대조라는 우회 논증으로만 도달했고, 논증 강도가 약하다(mtime은 내용 동일성의 직접 증명이 아니다). 검증에서 조사자 3이 유일하게 감점된 항목이 정확히 여기다 — "실행되는 정책"은 복원했으나 "등록된 정책 산문 + 해시 조인"은 못 했다.

### 자신 있게 틀린 복원 — 0건

검증자 3인 모두 `wrong` 판정 0건. 비도구 경로가 확신 있게 헛짚는 위험은 이 사건에서 **관측되지 않았다.** 조사자 3은 미확보 항목을 스스로 "실행되는 정책이지 등록된 정책 산문이 아니다"라고 선언하고 확신을 4로 낮췄다.

### 복원된 사건의 실체 — 오탐

차단된 명령에 파괴적 git 행위는 **한 줄도 없었다.** T4 워크트리에서 CLI 종단 스모크(GuardSpec 등록 → 사건 시드 → 과금 승인 없는 판정 dry-run)를 돌리는 복합 셸 명령이었고, heredoc 안 GuardSpec 초안 JSON의 `block_examples` 리터럴 `"git push --force"`가 패턴 `push --force`에 걸렸다. 가드 스크립트는 명령 문자열 전문을 8개 패턴에 `grep -qE`하며 인용·heredoc·문서 텍스트를 구분하지 않는다(`~/.claude/hooks/block-dangerous-git.sh:6-22` — 직접 확인). 02:28의 두 번째 사건도 같은 패턴의 재발이다.

**정책 판정과 유용성 검토는 별도 절차이므로 여기서 값을 매기지 않는다.** 다만 검토 큐 2건이 같은 성격이라는 사실은 확인됐다.

## 이 기준선을 읽을 때의 한계

1. **최선 조건의 측정이다.** transcript가 2026-08-10~09-01 전량 잔존하고, 저장소 문서가 잘 정비돼 있다(`관찰-프로토콜.md`가 가드 id·버전을 평문으로 담아 I1·I6의 일부를 그냥 준다). 기록이 소멸한 조건에서는 비도구 경로가 붕괴한다 — **이 값은 도구에 불리한 쪽 상한선으로 읽어야 한다.**
2. **조사자가 사람이 아니다.** 프로토콜의 "소요 시간(분)"을 조사 에이전트의 실측 wall-clock과 도구 호출 수로 조작화했다. 사람의 분 단위와 같은 척도가 아니며, 이후 비교는 **같은 조작화로만** 해야 한다. 이 조작화는 E5에서 관찰 프로토콜 "변경 기록"에 추기한다.
3. **n=1 사건**이다. 3인×2경로로 경로 내 분산은 줄였지만 사건 간 분산은 측정하지 않았다.
4. **발동이 서브에이전트에서 일어났다.** 레코드의 `session_id`는 부모 세션 것인데 실제 발동은 서브에이전트 컨텍스트였고, 레코드에 서브에이전트 식별자가 없어 두 경로 모두 `subagents/` 하위를 따로 뒤져야 했다. 양쪽 경로에 공통으로 든 비용이라 비교에는 영향이 없지만, 실제 복원 비용의 일부다.

## 후속으로 넘길 것

- **E5 추기**: 위 한계 2(측정 조작화)를 "변경 기록"에 남긴다.
- **O2 평가 입력**: "조회 표면만으로 5/6"은 도구의 가치 주장을 좁힌다 — 조회 표면은 **판정 맥락을 완결하지 않고**, 의도와 명령 내용은 여전히 transcript에 의존한다. 이건 결함이 아니라 비협상 ⑤·⑥이 선택한 대가이므로, 종료 보고에서 "무엇을 얻고 무엇을 포기했는가"로 병기해야 한다.
- **E3 관련 관찰**: E3는 준수 ID의 별칭화를 부분문자열까지 넓힌다. 파일시스템 접근이 있는 운영자에게는 영향이 없지만(원본 레코드는 그대로), **조회 표면만 쓰는 소비자에게는 transcript 조인이 더 멀어진다.** 계약 위반은 아니고 002가 의도한 방향이지만, 그 대가가 이번 측정으로 정량화됐다(6항목 중 1개 + 1개의 구체성).
- **검토 큐 2건**: 둘 다 오탐 성격으로 확인됐다. 판정·검토 실행은 `--approve-billing`이 필요한 별도 절차다.

2. **교정은 판정 일치를 보장하지 않는다.** 교정은 가드의 allow/block 예시를 맞히는지만 본다. 예시를 다 맞히고도 실제 사건에서 갈릴 수 있다는 것이 실측됐다 — 적대 리뷰 C7("판정기 신뢰도 검증 장치 전무")이 지적한 공백이 남아 있음을 뒷받침한다.
3. **판정 값은 모델·설정에 딸린 값이다.** 지표를 읽을 때 `model_id`·`model_settings_hash` 없이 판정만 인용하면 안 된다.

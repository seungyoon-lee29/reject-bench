## 3자 수렴한 목적 요약

> 이미 운영 중인 v1 도구가 관측창 4주를 버티는 동안 스스로 만들어내는 누수를 메우는 정비 증분이다. 누수는 하나로 이어져 있다 — 차단 사유를 4000자에서 맹목 절단하면 홈 경로·세션 ID가 반토막 조각으로 남고, 조회 표면은 값 전체·완전한 토큰만 가리므로 그 조각을 못 알아본다. 그래서 적재 쪽에서 온전한 덩어리만 남기고(E1), 세션 ID 형식을 적재 시점에 검사해 기록하며(E2), 출력 쪽에서 형식 준수 ID에 한해 단어 속에 파묻힌 등장까지 별칭으로 덮어 "원문 0회"를 실제 보장으로 승격시킨다(E3). 나머지는 정리다 — 옛 수집기 훅 4건과 파일을 걷어내고(E4), 관측창이 열린 상태에서 계측기를 바꿨다는 사실과 1차 관측 무대가 취소됐다는 사실을 선등록 프로토콜에 추기한다(E5).

**세 요약이 사실상 동일하다.** 셋 다 독립적으로 "E1→E2→E3이 하나의 누수 사슬"이라는 구조와 "관측 중인 실험의 계측기를 관측 중에 고친다"는 긴장을 짚었다. 문서의 목적 전달력은 검증됐다.

**C6. 이 작업 세션 자체의 자기차단 발동을 어떻게 처우하는지가 없다** 〔A-F3 + B-F5〕

- 두 리뷰어가 서로 다른 귀결을 짚었고 둘 다 미정이다.
  - **(a) 산입 여부** 〔A〕: 플래그 없는 발동은 자동으로 `operation`이고(`관찰-프로토콜.md:42`), C3에 따라 남는 사건원이 사실상 "reject-bench를 개발하다 걸리는 자기차단"뿐이다. 그러면 최소 성공(`기획-입력.md:43` "여러 세션 **자연** 발동")의 분자·분모가 **도구를 만드는 행위가 생성한 사건**으로 채워지는데, 그것이 산입 가능한 자연 발동인지 어느 문서도 판정하지 않는다. `docs/adr/0001…:11`이 형제 관계의 순환(관측용 가드 신설)을 이미 기각한 바 있어, 무판정으로 하류에 넘기면 **가치 판정 결과가 나온 뒤에** 산입 여부를 정하게 된다.
  - **(b) 측정 기회 소진** 〔B〕: 그 발동이 **첫 자연 operation 사건**일 때 무엇을 해야 하는지가 없다. 빌드는 기준선 측정을 범위 밖으로 밀었고(`spec.md:20`), 하드 게이트 3은 빌드 중 도구 조회를 금지하며(`handoff.md:28`), `관찰-프로토콜.md:32`는 "도구 보고서를 열람하기 전에" transcript+git 복원을 요구한다. 셋이 동시에 걸리면 실행자는 사건을 인지하고도 지나가고, **기준선 측정 기회 1회는 회복 불가로 소진된다.**
- 권고: (a) E5 추기에 "도구 자체 개발 세션의 발동 산입 규칙"을 넣을 것 — 산입한다면 한계를 보고서 병기 항목으로 못 박고, 산입하지 않는다면 그 사건들이 받는 값(별도 표기? `test` 강등?)을 정한다. `관찰-프로토콜.md:44`의 "관측 도중 새 가드 등록은 별도 표기"가 선례 형식이 된다. (b) plan에 태스크와 무관한 "상시 트리거" 절 — "빌드 중 전역 가드 자연 발동을 인지하면 태스크를 멈추고 `관찰-프로토콜.md` 기준선 측정 1~2단계(transcript+git 복원)만 먼저 수행한다. 3단계(도구 경로)는 빌드 완료 후" — 를 넣을 것. 이러면 하드 게이트 3과 충돌하지 않는다.

# 기록기 배선 목록과 cutover 대사

작성 2026-08-29. T3 배선의 정본 목록. 변경 시 이 문서를 함께 갱신한다.

## 새 배선 (v7 래퍼)

래퍼는 가드의 stdout/stderr/종료 코드를 그대로 투명 전달하고, 차단(exit 2 또는 deny JSON)일 때만 GuardEvent를 최선 노력으로 기록한다. 기록 실패는 가드 결과를 바꾸지 않는다. 저장은 reject-bench 중앙(`data/v7`) — 래퍼 패키지 위치 기준이라 어느 저장소에서 실행돼도 중앙으로 모인다.

| 위치 | 이벤트 | 기존 명령 | 새 명령 |
|---|---|---|---|
| `~/.claude/settings.json` | PreToolUse (matcher `Bash`) | `~/.claude/hooks/block-dangerous-git.sh` | `uv run --project /Users/ian/workspace/reject-bench python -m rejectbench.wrapper --guard /Users/ian/.claude/hooks/block-dangerous-git.sh` |
| `reply-gate/.claude/settings.json` | PreToolUse (matcher `Edit\|Write\|MultiEdit\|NotebookEdit\|Bash`) | `"$CLAUDE_PROJECT_DIR/.claude/hooks/protect-live-reports.sh"` | `uv run --project /Users/ian/workspace/reject-bench python -m rejectbench.wrapper --guard "$CLAUDE_PROJECT_DIR/.claude/hooks/protect-live-reports.sh"` |

- 가드 스크립트 자체는 수정하지 않는다 — 호출 지점만 래퍼를 경유한다.
- Codex 배선(`reply-gate/.codex/config.toml`의 protect-live-reports codex 경로)은 **바꾸지 않는다** — Codex 세션은 v1 관측 범위 밖(관찰 프로토콜 참조). 가드 자체는 기존대로 동작한다.
- 타임아웃은 기존 값(10s)을 유지한다.

## v0 배선 (현행 유지 — 퇴역은 별도 결정)

`hooks/collect.py`는 `~/.claude/settings.json`의 4개 이벤트에 남아 있다: PostToolUse(Edit|Write|MultiEdit|NotebookEdit), PostToolUseFailure(*), PermissionRequest(*), PermissionDenied(*).

## cutover 대사

- v0은 일반 도구 실패·권한 이벤트를 넓게 수집하지만 **가드 차단을 구조화해 잡지 못한다**(v7 문제의식의 출발점).
- 새 배선은 관측 대상 가드 2종의 PreToolUse 차단을 구조화 캡처한다. 두 배선은 이벤트가 겹치지 않으므로(PreToolUse vs Post/Permission 계열) 병행 운영에 충돌이 없다.
- 관측 공백 점검: 가드 2종의 발동 경로는 전부 PreToolUse이며 두 호출 지점 모두 래퍼를 경유한다 → 새 배선 기준 공백 없음. 단 Codex 세션의 reply-gate 가드 발동은 범위 밖 공백으로 프로토콜에 선언됨.
- `hooks/collect.py` 퇴역 여부는 이 병행 상태를 확인한 뒤 별도 커밋으로 결정한다(HANDOFF 미결 3).

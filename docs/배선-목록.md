## 새 배선 (v7 래퍼)

래퍼는 가드의 stdout/stderr/종료 코드를 그대로 투명 전달하고, 차단(exit 2 또는 deny JSON)일 때만 GuardEvent를 최선 노력으로 기록한다. 기록 실패는 가드 결과를 바꾸지 않는다. 저장은 reject-bench 중앙(`data/v7`) — 래퍼 패키지 위치 기준이라 어느 저장소에서 실행돼도 중앙으로 모인다.

|---|---|---|---|
| `~/.claude/settings.json` | PreToolUse (matcher `Bash`) | `~/.claude/hooks/block-dangerous-git.sh` | `PYTHONPATH=/Users/ian/workspace/reject-bench /Users/ian/.local/bin/uv run --project /Users/ian/workspace/reject-bench python -m rejectbench.wrapper --guard /Users/ian/.claude/hooks/block-dangerous-git.sh` |

### E0 배선 수정 (2026-09-01) — 인라인 `PYTHONPATH` 접두

**증상**: `pyproject.toml:15`가 `package = false`라 프로젝트가 venv에 설치되지 않고, `python -m`은 호출 시점 cwd로 패키지를 찾는다. 저장소 밖 cwd의 세션에서는 래퍼가 `ModuleNotFoundError`로 죽어 **가드 발동이 한 건도 기록되지 않았다.** 선등록 관측 범위(`관찰-프로토콜.md:11` "Claude Code가 도는 모든 저장소 세션")가 그 구간에 대해 거짓이었다 — 소급 정정은 E5④.

**수정**: 위 표의 새 명령에 `PYTHONPATH=/Users/ian/workspace/reject-bench ` 접두를 넣었다. 명령의 나머지·타임아웃(10s)·matcher·다른 훅 항목은 불변.

**절차**(하드 게이트 5): 스냅샷 `~/.claude/settings.json.rejectbench-pre-e0-20260901`(사용자 소유 `.bak-*`와 다른 이름) → 대상 명령 문자열이 정확히 1회 나타남을 확인 → 문자열 정밀 교체 → JSON 파싱·항목 수·최상위 키·길이 변화량 검증 → 임시 파일에 쓰고 원자적 교체.

**읽기 조회 캡처** — 대상이 git 밖이라 커밋 diff로는 사후 재구성이 불가능하므로 그대로 적는다.

## v0 배선 (퇴역 완료 — 2026-09-02)

`hooks/collect.py`는 `~/.claude/settings.json`의 4개 이벤트 — PostToolUse(Edit|Write|MultiEdit|NotebookEdit), PostToolUseFailure(*), PermissionRequest(*), PermissionDenied(*) — 에 걸려 있었고, 003 주기 E4가 그 호출 4건을 제거하고 파일을 삭제했다. 일반 텔레메트리 수집 종료는 사용자 결정이다(003 `handoff.md` 저작 시점 의도) — "혹시 몰라 남기자"로 파일·배선을 되살리지 않는다. 수집 원천 `data/events.jsonl`과 연속성 훅(`hooks/continuity.py`·`hooks/codex_handoff_gate.py`와 각 테스트)은 보존한다.

### E4 v0 수집기 퇴역 (2026-09-02)

**절차**(하드 게이트 5): 스냅샷 `~/.claude/settings.json.rejectbench-pre-e4-20260902`(사용자 소유 `.bak-*`와 다른 이름, 바이트 일치 확인) → 메모리에서 `hooks/collect.py`를 부르는 훅만 제거(정확히 4건인지 사전 확인) → 임시 파일 `settings.json.rejectbench-e4-tmp`에 원본 서식(들여쓰기 2·비ASCII 원문·끝 개행·모드 644)대로 쓰고 재파싱 → 검증 3종 + "나머지 항목 불변"(제거 전 collect.py 외 항목 열과 제거 후 전체 열이 동일) → 원자 교체 → 교체 후 재검증. 어느 단계든 실패하면 스냅샷에서 복원하도록 스크립트에 박아 두었고, **복원은 발동하지 않았다.**

## cutover 대사

- v0은 일반 도구 실패·권한 이벤트를 넓게 수집했지만 **가드 차단을 구조화해 잡지 못했다**(v7 문제의식의 출발점).
- 새 배선은 관측 대상 가드 2종의 PreToolUse 차단을 구조화 캡처한다. 두 배선은 이벤트가 겹치지 않았으므로(PreToolUse vs Post/Permission 계열) 병행 운영에 충돌이 없었다.
- 관측 공백 점검: 가드 2종의 발동 경로는 전부 PreToolUse이며 두 호출 지점 모두 래퍼를 경유한다 → 새 배선 기준 공백 없음. 단 Codex 세션의 reply-gate 가드 발동은 범위 밖 공백으로 프로토콜에 선언됨.
- v0 수집기 퇴역은 이 병행 상태를 확인한 뒤의 별도 결정이었고(루트 `HANDOFF.md`의 미결 항목 "v0 수집기 퇴역" — 번호가 아니라 항목명으로 가리킨다), 2026-09-02 E4로 완료됐다(위 절).
